# The Patent War — 특허 전쟁

웹 브라우저에서 바로 돌아가는 **3D 1인칭 슈팅(FPS) 팀 전투 게임**입니다.
플레이어는 특허청 조직 **KIPI** 소속 요원이 되어, 특허를 탈취하려는 적대 조직 **X-KIPI**와 싸우며
특허가 의인화된 NPC **'발명이'**를 처치해 무기를 강화하고 상대 팀 요원을 전멸시키는 것이 목표입니다.

구현 기준 문서: `특허전쟁_개발로드맵.md` (프로토타입 v3.7 스펙 / 이 저장소 밖에 보관)

## 실행 방법

빌드도, 설치도, 서버도 필요 없습니다. 파일 하나를 브라우저로 열면 끝입니다.

```bash
start index.html
```

> Three.js를 CDN(cdnjs)에서 불러오므로 **최초 실행 시 인터넷 연결이 필요**합니다.
> 그 외 이미지·사운드·폰트 등 외부 자산 파일은 **하나도 사용하지 않습니다.**

### 조작

| 입력 | 동작 |
|---|---|
| 마우스 이동 | 시점 회전 (화면 가장자리에서 연속 회전) |
| 좌클릭 / 꾹 누르기 | 마법탄 발사 / 연사 (120ms 간격) |

| 사다리 앞에서 `W` / `S` | 오르기 / 내려오기 |

## 파일 구성

```
patent war/
├─ public/
│  └─ index.html  ← 게임 전체 (HTML + CSS + JS 단일 파일)
├─ server.js       ← 정적 서빙 + 랭킹 API (/api/scores, /api/ranks)
├─ package.json    ← start 스크립트 + express 의존성
├─ README.md       ← 이 문서
└─ .gitignore
```

**왜 게임 화면이 단일 파일인가**: 로드맵 §2.1에서 게임 자체의 배포 형태를 "단일 .html 파일 / 외부 자산 파일 없음"으로 확정했습니다.
파일 하나만 주고받으면 어디서든 실행되고, 경로 문제·CORS·빌드 파이프라인이 전부 사라집니다.
대신 파일이 길어지므로, 아래처럼 **섹션 주석으로 모듈 경계를 명시**해 두었습니다.

랭킹 화면이 `/api/scores`(점수 등록)와 `/api/ranks`(순위 조회)를 호출하므로, 이 두 API만 제공하는
가벼운 Express 서버(`server.js`)를 추가했습니다. 순위 데이터는 메모리에만 저장되므로(공모전
1회성 시연 목적, 별도 DB 없음), Render 무료 플랜에서 15분간 트래픽이 없어 인스턴스가 슬립되면
재기동 시 랭킹이 초기화됩니다 — 시연 전날 미리 한 번 깨워두는 것을 권장합니다.

### 로컬 실행

```bash
npm install
npm start   # http://localhost:3000
```

## 주요 시스템 설명

### 1. 물리 — 자체 AABB 충돌 엔진

외부 물리 엔진을 쓰지 않고 직접 구현했습니다. 캡슐 대신 **원기둥 근사**를 씁니다.

- 모든 구조물은 `slab()`으로 만들며, 생성과 동시에 `colliders[]` 배열에 AABB가 등록됩니다.
- 이동은 **X축·Z축을 분리 검사**합니다. 그래서 벽에 비스듬히 부딪히면 자연스럽게 미끄러집니다.
- 1차 검사가 막히면 `+0.46m` 높이에서 재검사 → **낮은 턱은 자동으로 올라갑니다.**
- `supportAt()`이 발밑 지지면을 찾아, 컨테이너·옥상 위에 **실제로 서 있을 수 있습니다.**
- **탄환도 같은 AABB에 막힙니다** (`boltHitWall()`, slab method). 이게 없으면 엄폐가 전술이 되지 않습니다.

### 2. 시점 — 포인터락 없는 1:1 마우스 추적

FPS 멀미를 막기 위해 로드맵 §7.2에서 다섯 가지 원칙을 확정했고, 코드가 그대로 따릅니다.

1. OS 커서 숨김 (`body.ingame { cursor:none }`)
2. 크로스헤어는 **항상 화면 정중앙 고정**
3. 조준 방향 = 화면 중앙 방향 ("보는 곳 = 쏘는 곳"이 항상 일치)
4. **헤드밥 없음** (걷기 출렁임·숨쉬기 흔들림 모두 제거)
5. **시점 스무딩 없음** — 마우스 입력을 지연 없이 즉시 반영

마우스 X 위치가 화면 가장자리(±0.85)를 넘어가면 `EDGE_SPD`(3.0 rad/s)로 연속 회전해,
포인터락 없이도 360도를 다 볼 수 있습니다.

### 3. 전투

```
플레이어 데미지 = (6 + 무기레벨 × 2) × (공격력버프 ? 2 : 1) × (헤드샷 ? 2 : 1)
```

- **무기는 마법탄 1종 고정**, 탄약 무제한, 재장전 없음. 사거리 30m를 넘으면 데미지 없이 소멸합니다.
- **발명이 10마리 처치마다 무기 레벨 +1** (플레이어가 직접 처치한 것만 카운트).
- 헤드샷 판정은 `headYOf()`가 계산한 머리 높이 기준, 수평거리 0.55m·수직 0.4m 이내일 때 성립합니다.
- 히트마커는 3단계로 구분됩니다 — 일반(흰색) / 헤드샷(노랑) / 처치(빨강).

### 4. 봇 AI

**핵심 원칙**: 난이도가 올라가도 봇이 더 강해지는 게 아닙니다.
체력·데미지·이동속도는 전 난이도 동일하고, **명중률·공격 빈도·지능만** 달라집니다.

| 난이도 | 발사 주기 | 탄 퍼짐 | 지능 |
|---|---|---|---|
| 초보 | 5.5초 | 4.5° | 랜덤 타겟, 소극적 교전 거리(6~13m) |
| 중수 | 4.0초 | 2.4° | 랜덤 타겟 |
| 고수 | 2.8초 | 1.0° | **체력 낮은 대상 집중**, 공격적 접근(4~10m) |

요원 봇은 0.18초마다 반경 26m를 스캔하고, **시야선(LOS)이 막히면 적을 발견하지 못합니다.**
적을 못 찾으면 웨이포인트 16곳을 순찰하며, 1.4초간 진척이 없으면 끼임으로 판단해 경로를 다시 뽑습니다.
봇은 플레이어와 **완전히 동일한 충돌 엔진**을 쓰므로 턱도 오르고 옥상에도 올라갑니다.

### 5. 발명이와 웨이브

발명이는 각 팀에 소속되어 함께 싸우면서, 동시에 상대 팀이 처치해야 하는 대상입니다.

| 변종 | 체력 | 속도 | 특징 |
|---|---|---|---|
| `normal` | ×1.0 | ×1.0 | 기본 (웨이브 1은 전부 이것) |
| `tank` | ×2.2 | ×0.6 | 느리고 단단함 |
| `runner` | ×0.55 | ×1.8 | 빠르고 물렁함 |
| `bomber` | ×0.8 | ×1.4 | 접근 후 자폭(반경 3.5m). 몸이 빨갛게 점멸하며 경고 |

적 발명이 6마리를 처치하면 다음 웨이브로 넘어가고, 웨이브마다 기본 체력이 +40씩 오릅니다.
발명이는 목숨 개념 없이 2.6초 뒤 무한 리스폰되며, 리스폰할 때 변종과 체력을 다시 굴립니다.

### 6. 맵 — 뉴 정크 시티

오버워치 「뉴 정크 시티」를 **디자인뿐 아니라 레인 구조·전략 설계까지** 참고했습니다.

- 약 **56m × 58m**, 남쪽 KIPI ↔ 북쪽 X-KIPI 대칭 배치
- **3레인** (서: 컨테이너 골목 / 중앙: 고철 처리장 / 동: 폐건물)
- **고지대 5곳**, 높이 6단계 (0 → 1.15 → 1.4 → 2.6 → 3.15/3.3/3.75 → 5.2)
- 사다리 3곳, 계단 2곳. 사다리는 **정상에 닿으면 자동으로 플랫폼 위로 밀어냅니다** (떨어지는 버그 방지)
- 중앙 고철 처리장이 맵을 관통하는 시야를 완전히 차단하는 핵심 오브젝트입니다

### 7. LIFE 시스템

- 플레이어·봇 요원 모두 **목숨 3개**
- 사망 시 10초 후 부활, 부활 직후 2초 무적
- 목숨을 다 쓰면 **리스폰 없이 아웃**. 플레이어가 아웃돼도 팀원 봇이 살아 있으면 게임은 계속되고, 플레이어는 관전 상태로 시점만 조작할 수 있습니다
- **팀 점수는 요원 처치 수만** 셉니다. 발명이 처치는 무기 강화와 웨이브 진행에만 쓰입니다

## 밸런스 조정 방법

수치는 전부 **`CONFIG` 한 곳(678행)** 에 모아 뒀습니다. 코드 곳곳을 뒤질 필요가 없습니다.

```javascript
const CONFIG = {
  player: { hp:150, lives:3, respawn:10, walk:5.5, sprint:9.0, jump:6.3, ... },
  weapon: { range:30, speed:36, rof:120, dmgBase:6, dmgPerLv:2, lvUpKills:10 },
  skills: { dash:{cd:6, dur:0.16, speed:26}, shield:{cd:10, dur:2.5} },
  buffs:  { atk:{mul:2, dur:10}, spd:{mul:1.35, dur:8} },
  npc:    { baseHp:150, hpPerWave:40, waveSize:6, respawn:2.6, ... },
  diff:   { '초보':{int:5.5, miss:4.5, smart:0}, ... },
  match:  { time:300, countdown:3, onboarding:5, endDelay:2 },
};
```

예를 들어 "한 판이 너무 길다" 싶으면 `match.time`만, "발명이가 너무 질기다" 싶으면 `npc.baseHp`만 고치면 됩니다.

## 코드를 고칠 때 주의할 점

로드맵 §20.4에 명시된 규칙입니다. 어기면 조용히 버그가 생깁니다.

1. **새 구조물은 반드시 `slab()`으로 만들 것.** `scene.add()`를 직접 호출하면 `colliders[]`에 등록되지 않아 **관통 버그**가 납니다.
2. **원기둥·구체 구조물은 `collAt()`을 따로 호출**해야 합니다 (파이프·타이어·연료탱크가 그 예).
3. **새 엔티티는 반드시 `addEntity()`를 거칠 것.** 이름표와 상태 필드가 함께 초기화됩니다.
4. **새 상태 변수를 추가하면 `resetMatch()`에도 초기화 코드를 넣을 것.** 안 그러면 재시작 시 이전 판 값이 남습니다.
5. **`matchSeq` 가드를 유지할 것.** 리스폰·킬피드가 `setTimeout`으로 돌기 때문에, 매치를 재시작하면 이전 판의 콜백이 유령처럼 살아나 새 판을 오염시킵니다. 모든 지연 콜백은 `if(seq !== matchSeq) return;`으로 막혀 있습니다.
6. **애니메이션을 추가할 때 `animEntity()`의 8방향 분해 로직을 건드리지 말 것.** 상하좌우 4방향만으로는 옆걸음이 부자연스러워집니다.

### 다시 시도하면 안 되는 것들

로드맵 §19.2에 실패 기록으로 남은 접근입니다.

- 시작 오버레이 / 포인터락 강제 / 모드 분기 → "완전히 이상해졌다"
- 시점 스무딩 필터 → 빠른 플릭이 반영되지 않음
- 커서 조준 모드(카메라 고정 + 크로스헤어가 커서 추적) → FPS답지 않음
- 메뉴 뒤에 3D 게임 월드 렌더 → "이미 게임이 도는 건가?" 혼란 유발
- 초록 피부 발명이 → 컨셉과 불일치 (차콜 수트 + 크림 얼굴이 정답)
- 사거리 무제한 → 맵 끝에서 저격 가능
- 철문 애니메이션 0.16초(인위적) / 0.38초(느림) → **0.26초가 정답**
