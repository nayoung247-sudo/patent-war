# The Patent War — 특허 전쟁

특허청(KIPI) 컨셉의 3D 1인칭 슈팅 게임. **3분 안에 최대한 많은 점수를 쌓는 점수제**이며,
싱글과 **2인 협동**을 지원합니다.

Three.js r128 하나만 CDN으로 불러오는 **단일 HTML 파일**(`public/index.html`)이라 빌드 도구가 없습니다.
랭킹과 협동 플레이는 `server.js` 하나가 전부 담당합니다.

---

## 실행

```bash
npm install
npm start
```

`http://localhost:3000` 접속. 이 서버 하나가 게임 파일 · 랭킹 API · 협동 릴레이를 **동시에** 처리합니다.

게임 파일만 브라우저로 직접 열어도 싱글 플레이는 정상 동작합니다. 랭킹과 멀티만 "서버에 연결하지 못했습니다"로 표시됩니다.

### Render 배포

| 항목 | 값 |
|---|---|
| Environment | Node |
| Build Command | `npm install` |
| Start Command | `npm start` |
| Instance Type | **유료 플랜 권장** |

WebSocket은 같은 포트의 `/ws` 를 씁니다. 별도 설정이 필요 없습니다.

> 무료 인스턴스는 15분 유휴 후 잠들고(첫 요청에 약 1분), 10팀 동시 접속에는 CPU가 빠듯합니다.
> 행사 운영이라면 유료 플랜을 쓰고, 무료로 간다면 시작 30분 전에 URL을 한 번 열어 깨워 두세요.

## 세계관

한국특허정보원의 데이터베이스에는 수많은 **발명이**가 살고 있습니다. 우리가 지켜 온 지식재산 그 자체입니다.
특허를 빼앗으려는 **악의 세력**이 데이터베이스에 침투해 발명이를 그대로 베낀 **가짜**들을 만들어냈고,
진짜와 구분하기 어려울 만큼 정교한 이 가짜들이 몬스터가 되어 우리 데이터를 향해 몰려옵니다.
플레이어는 정보원의 요원으로서 시간이 끝날 때까지 버티며 이들을 걸러냅니다.

- 메인 화면 **[스토리]** 버튼에서 한 장짜리 스토리 이미지로 볼 수 있습니다(`scrStory`).
- 점수는 그냥 점수입니다. 대신 결과 화면 상단에 **이번 전투의 결말 문구**가 붙습니다(아래 「결과 화면」 참고).
- 적 이름은 **발명이**로 고정입니다. 진영전(KIPI vs X-KIPI) 구도는 쓰지 않습니다.

## 게임 규칙

| 항목 | 내용 |
|---|---|
| 제한 시간 | **180초** (`MATCH_TIME`) |
| 목표 | 발명이와 대장급을 처치해 **점수**를 쌓기 |
| 웨이브 진행 | **시간이 아니라 처치 할당량**으로 넘어감 |
| 목숨 | **3개** (`MAX_LIVES`) — 쓰러지면 하나 소모하고 **3초 뒤 부활**, 다 쓰면 더 부활하지 않는다 (연속 처치는 끊김). 남은 개수는 화면 **왼쪽 아래 LIFE** 에 하트로 보인다 |
| 끝나는 조건 | ① **5웨이브까지 모두 완수**(할당량 + 대장 2마리) → 3분 전이라도 즉시 **작전 성공**, 남은 시간 1초당 **100점 보너스** ② 시간 종료 ③ **목숨 소진** → 즉시 **작전 실패** |
| 협동에서 목숨 소진 | 동료가 아직 남아 있으면 **판은 계속**되고 소진한 쪽은 관전한다. **둘 다 소진**하면 판이 끝난다 (종료 선언은 방장) |
| 랭킹 | 철저히 **점수순** |

### 점수

| 대상 | 점수 |
|---|---|
| 발명이 | 100 ~ 250 (변종별) |
| 발명 대장 | 2,500 |
| 특허 파괴자 | 4,000 |
| 약점(머리) 명중 | 피해 **2배** |
| 연속 처치 | 처치마다 ×0.15씩, 최대 **×2.5** (4.5초 안에 다음 처치) |

### 웨이브 (5개 고정, 처치 할당량제)

| # | 이름 | 등장 | 동시 최대 | 할당량 | 대장 |
|---|---|---|---|---|---|
| 1 | 잔당 소탕 | 발명이, 날쌘 | 8 | 12 | — |
| 2 | 날쌘 무리 | 발명이, 날쌘, 도약 | 10 | 17 | — |
| 3 | 대장 출현 | 발명이, 날쌘, 강철, 도약 | 10 | 21 | **발명 대장** |
| 4 | 포화 지대 | 날쌘, 강철, 포수, 자폭 | 12 | 25 | **특허 파괴자** |
| 5 | 총공세 | 전 종류 | 14 | 24 | **태엽 대장 2마리** |

**할당량을 채워도 대장이 살아 있으면 넘어가지 않습니다.** 잡몹을 다 잡고 대장까지 처치해야 다음 웨이브입니다.
상단 칩에 **"다음 웨이브까지 N마리"**(5웨이브는 **"승리까지 N마리"**)가 실시간으로 뜨고, 대장이 있으면 " · 대장 N마리"가 붙습니다.
새 웨이브가 시작되면 **조준점과 웨이브 칩 사이에 "더 강력한 발명이가 등장했습니다!"** 가 약 3초 크게 떴다 사라집니다(`showWaveBanner()`).

5웨이브는 할당량 24마리를 채우고 **태엽 대장 2마리**까지 쓰러뜨리면 그 자리에서 끝납니다(`winMatch()`).

**웨이브가 넘어가면 이전 웨이브 잔당은 소멸 연출과 함께 정리됩니다.** 잡지 않았으므로 점수·처치 수는 주지 않습니다.

> 난이도 조정은 `WAVES` 배열의 `quota`(할당량)와 `max`(동시 최대)만 고치면 됩니다.
> 스폰 공급량 기준 시뮬레이션으로는 웨이브1 18초, 2는 39초, 3은 86초, 4는 149초에 끝나
> 마지막 약 30초가 총공세 구간이 됩니다. 대장이 나오는 시점은 일시정지와 무관하게 전투 시간으로 셉니다(`bossQueue`).

## 캐릭터 4종

출전 준비 화면에서 이름을 입력하고 하나를 고릅니다. 초상은 실제 3D 모델을 그대로 렌더해서 씁니다.

| 캐릭터 | 역할 | 체력 | 화력 | 속도 | 쿨다운 |
|---|---|---|---|---|---|
| **정보요원** | 균형 | 150 | ×1.00 | ×1.00 | 6초 |
| **심사관** | 화력 | 130 | ×1.25 | ×0.97 | 6초 |
| **분석관** | 기동 | 125 | ×0.95 | ×1.15 | 4초 |
| **수호관** | 방어 | 200 | ×0.92 | ×0.92 | 7초 |

수치는 `LOADOUTS` 배열에 모여 있고 `applyLoadout()` 이 `pMaxHp / pDmg / pSpd / pDashCd` 에 반영합니다.
이 빌드에는 대시가 없어서 **쿨다운 능력치는 Q 마법 실드에 적용**됩니다.

### 어느 모드로 들어왔는지

출전 준비 화면 제목 아래에 **모드 배지**가 붙습니다. 싱글이면 사람 한 명 아이콘과 "싱글 플레이 · 혼자 기록에 도전",
멀티면 두 명 아이콘과 "멀티 플레이 · 방을 골라 2인 협동". 하단 버튼도 싱글은 [다음], 멀티는 [방 고르기]로 바뀝니다(`setModeTag()`).

### 플레이어 이름 자동 생성

출전 준비 화면에 들어가면 이름이 **이미 채워진 상태**입니다.
감정 30개 × 성씨 40개 × 직급 9개 = **10,800가지** 조합이며 전부 8자 이하입니다. (`NAME_MOOD` / `NAME_SURNAME` / `NAME_RANK`)

- 예: `신난 노본부장`, `깐깐한 이실장`, `행복한 최부장`
- 옆 **🎲 버튼**으로 다시 뽑기
- 자동 생성된 이름은 입력칸을 처음 누를 때 **전체 선택**되어 바로 덮어쓸 수 있습니다. 한 번이라도 직접 고치면 이 동작은 꺼집니다.

## 적 캐릭터

### 발명이 변종 6종

| 키 | 이름 | 특징 | 체력배율 | 속도배율 | 점수 |
|---|---|---|---|---|---|
| normal | 발명이 | 기본 추격·근접 | 1.0 | 1.00 | 100 |
| runner | 날쌘 발명이 | 빠름, **지그재그**로 접근 | 0.55 | 1.55 | 150 |
| tank | 강철 발명이 | 단단하고 느림 | 3.2 | 0.58 | 200 |
| bomber | 자폭 발명이 | 접근 후 폭발 | 0.8 | 1.22 | 160 |
| spitter | 포수 발명이 | **거리를 유지하며 원거리 사격** | 0.9 | 0.85 | 180 |
| jumper | 도약 발명이 | **주기적으로 크게 뛰어** 거리를 좁힘 | 1.1 | 1.00 | 250 |

기본 체력 `NPC_BASE_HP=34`, 웨이브마다 `NPC_WAVE_HP=16` 씩 추가.
추격 속도 `NPC_CHASE=2.15`, 사냥 이동 `NPC_HUNT=1.9`.

플레이어 걷기가 5.5, 질주가 9.0이므로 **가장 빠른 날쌘 발명이도 걷기의 61%** 입니다. 걸으면서 거리를 벌 수 있습니다.

### 대장급

| 대장 | 등장 | 외형 | 체력 | 패턴 |
|---|---|---|---|---|
| 발명 대장 | 3웨이브 | 포탑 로봇 대장판 | 2,200 | **3점사** + 가끔 돌진 |
| 특허 파괴자 | 4웨이브 | 사이렌 모니터 대장판 | 3,400 | **부채꼴 5발** + 미니언 소환 |
| 태엽 대장 ×2 | 5웨이브 | **5웨이브 발명이(태엽 메카)의 대장판** | 각 2,600 | 한 마리는 3점사, 한 마리는 부채꼴+소환 |

대장 외형은 **그 웨이브에 나오는 발명이의 큰 버전**입니다(`BOSSES[].skin` = 해당 웨이브 외형 번호).

둘 다 체력 **45% 이하에서 광폭화**(`BOSS_RAGE`, 이동·공격 속도 상승)하며 화면 상단에 전용 체력바가 뜹니다.
5웨이브에서 두 마리가 함께 나올 때는 표시 중이던 대장이 죽으면 남은 대장으로 자동 전환됩니다.

### 외형

발명이의 **외형은 웨이브마다 순서대로 바뀝니다**. 변종·체력과는 별개로 겉모습만 도는 구조입니다.

| 웨이브 | 외형 |
|---|---|
| 1 | **발명이 인형** — 검은 알갱이 봉제 인형, 크림색 나이테 얼굴 |
| 2 | **정찰 드론** — 은빛 구체, 회전 프로펠러, 초록 눈 |
| 3 | **포탑 로봇** — 검은 각진 몸체, 보라 원통 머리, 오른팔 포신 |
| 4 | **사이렌 모니터** — 하늘색 화면 얼굴, 붉은 경광등, 케이블 다발 |
| 5 | **태엽 메카** — 붉은 몸통에 시계판, 위에 파랑새 |
| 6 | **뿔 블롭** — 분홍 몸, 보라 뿔, 이빨 입 |

### 스폰 — 매 판 달라집니다

고정 좌표를 쓰지 않습니다. **매치마다 스폰 지점 18곳을 새로 뽑습니다.**

- 구조물에 막히지 않고 서로 **7m 이상** 떨어진 지점 (`SPAWN_COUNT`, `SPAWN_APART`)
- 플레이어 시작 지점 반경 13m는 제외
- 두 매치를 비교하면 3m 이내로 겹치는 지점이 18개 중 **평균 3.3개(19%)** — 위치를 외울 수 없습니다

선택 규칙:

- 플레이어 **정면 11~26m** 를 우선 (찾아다니지 않아도 되게)
- 방금 쓴 지점은 **4.5초간 큰 감점** → 한 구멍에서 줄줄이 나오지 않음
- 상위 5곳 중 **무작위** 선택 + 주변 2.5m 흩뿌리기
- **한 지점당 최대 2마리.** 한 번에 2~4마리를 내보낼 때 지점을 나눠 배치합니다
  (시뮬레이션: 70%가 1마리, 30%가 2마리, 3마리 이상 없음)

### AI

- 시야에서 놓쳐도 **마지막 목격 지점을 5초 기억**한 뒤 수색
- 사냥 중 목표 갱신 주기 1~1.8초. 상대의 발밑이 아니라 **개체마다 고정된 접근 각도**로 상대 둘레(2.2~4.8m)를 노려, 사방에서 에워싸지 한 점에 몰리지 않습니다
- **개체끼리 밀어냅니다**(`crowdPush()`, `PERSONAL` · `CROWD_W`). 예전에는 봇 이동이 구조물만 검사해 발명이끼리 서로를 전혀 인지하지 못했고, 모두가 플레이어라는 같은 한 점으로 달려들어 그 자리에 통째로 겹쳐 쌓였습니다
- 발명이·대장은 전부 `spawnInventor()` / `spawnBoss()` 로 런타임 생성, 쓰러지는 연출이 끝나면 `removeEntity()` 가 씬에서 완전히 제거
- 한 묶음(2~4마리)은 **기본적으로 지점당 1마리씩** 나눠 내보냅니다(30% 확률로만 2마리). 지점당 2마리가 기본이면 묶음이 한두 곳에서만 쏟아져 처음부터 뭉쳐 보입니다
- 난이도는 화면에서 고르지 않고 **경과 시간에 따라 자동으로** 상승(`timeScale()`)
- X-KIPI 요원(적 봇)은 이 모드에서 등장하지 않습니다. `spawnAgent()` 는 남겨 두었지만 호출하지 않습니다

### 플레이어 시작 위치

**매 판, 매 부활마다 다른 곳**에서 시작합니다. 후보 9곳 중 **살아 있는 발명이에게서 가장 먼 곳**을 고릅니다(부활 직후 다굴 방지).

- 후보 좌표가 구조물과 겹치면 **실제 충돌 박스로 검사해 가장 가까운 빈자리**로 옮깁니다(`freePlayerSpot()`). 예전에 계단 고지·벙커에 끼어 점프해야 빠져나오던 문제를 막습니다.
- 시작·부활 시점은 **맵 중앙을 수평으로** 봅니다(`faceMapCenter()`). 예전 계산은 방향 부호가 뒤집혀 바깥 벽이나 하늘을 보고 시작했습니다.

## 맵 — 테마 3종 무작위

### 동서남북 랜드마크

플레이 구역 바깥에 실제 건물을 게임 무드(로우폴리 박스 + 도트 창문)로 옮긴 **배경 건물 4채**가 서 있습니다. 충돌·그림자 없는 순수 배경입니다.

| 방향 | 건물 | 특징 |
|---|---|---|
| 북 | 지식재산청사 | 쌍둥이 타워 + 안쪽 저층 날개 + 유리 피라미드 로비 |
| 동 | 한국특허정보원 | 유리 커튼월 타워, 사선 루버, 필로티 저층부 |
| 남 | 무역회관 | 흰 석재 타워, 중앙 검은 유리띠, 저층 시계 |
| 서 | 발명센터 | 거친 돌 기단 + 세로 창띠 + 코니스 |

- 창문은 캔버스 도트 텍스처라 건물당 박스가 10개 안팎입니다.
- **밤 테마에서는 창문 불빛이 켜집니다.**
- 게임 안개를 그대로 받으면 밤(95m)에 건물이 사라지므로, 랜드마크만 안개를 끄고 테마별 대기색(`haze`)을 섞습니다.
- 네 채 모두 **88m 거리**, 맵 중앙에서 살짝 올려다봤을 때 건물 전체가 한 화면에 들어오는 크기입니다. 타워 3채는 높이 약 73m, 석조 건물은 넓고 낮은 형태를 살려 높이 58m·폭 81m입니다.
- 배치·크기는 `LANDMARKS` 배열(`dir`, `dist`, `scale`, `side`)에서 조정합니다. `scale` 은 숫자(균일) 또는 `[가로·깊이, 높이]`.
- 예전 맵에 있던 KIPI / X-KIPI 간판 박스 건물은 제거했습니다.

### 테마

**맵 구조는 완전히 동일하고 하늘·안개·조명만 바뀝니다.** 매치 시작마다 무작위로 하나 고르며, 직전 판과 같은 테마는 피합니다.

| 테마 | 하늘 | 조명 | 비고 |
|---|---|---|---|
| 맑은 아침 | 밝은 하늘색 | 푸른 기 도는 흰 햇빛, 안개 옅음 | |
| 노을 | 주황 | 따뜻한 노란빛 | 기존 |
| 밤 | 짙은 남색 | 차가운 달빛, 안개 짙음 | **가로등 8개 점등** |

밤은 어두워서 난이도가 올라가므로 가로등으로 시야를 보정합니다. 테마 정의는 `THEMES` 배열, 적용은 `applyTheme(i)` / `randomTheme()`.
(왼쪽 위에 있던 "특허 전쟁 · 요원 · 맵 이름" 칩은 제거했습니다.)

협동에서는 **호스트가 뽑은 테마를 게스트에게 전달**해 양쪽이 같은 맵을 봅니다.

## 아이템

필드 아이템은 **단색 단순 도형**입니다. 텍스트 없이 실루엣과 색으로만 구분합니다.

| 아이템 | 모양 | 색 | 효과 | 필드 수 |
|---|---|---|---|---|
| 체력 회복 | 굵은 십자 | 초록 | 체력 50 회복 | 6곳 |
| 공격력 강화 | 검 | 주황 | 8초간 **3발 산탄** (중앙탄 ×1.5, 폭발 반경 1.85) | 2곳 |
| 이동 강화 | **파란 운동화** | 파랑 + 하늘색 | 8초간 이동속도 ×1.35 | 2곳 |
| **특허 폭탄** | 구체 + 도화선 | 보라 | **슬롯에 보관**, R로 사용 | 2곳 |

이동 강화는 흰 밑창 · 파란 갑피 · 흰 앞코 · 혀와 끈 · 옆줄까지 갖춘 운동화이고, 뒤로 하늘색 속도선 세 줄이 붙어 있습니다.
`roundBoxGeo` 로 모서리를 깎아 각지지 않습니다.

각 아이템은 바닥에 같은 색 원형 링이 깔려 위치가 잘 보입니다. 재생성은 30초(`ITEM_RESPAWN`), 그때는 **직전과 다른 위치**에 나타납니다.

무기 레벨업은 **처치 14마리**마다(`LEVEL_KILLS`).

### 특허 폭탄

필드에서 주우면 슬롯에 들어가고(**최대 1개**), **R** 을 누르면 **그 자리에서 즉시** 터집니다. 던지지 않습니다.

| 항목 | 값 |
|---|---|
| 반경 | 9.5m (`BOMB_RADIUS`) |
| 중심 피해 | 300 (`BOMB_DMG`) |
| 가장자리 피해 | 137 (45%까지 감쇠) |
| 연출 | 충격파 링 2겹 + 화면 흔들림 + 섬광 |

범위 안 일반 발명이는 확실히 죽고, 5웨이브 강철 발명이도 거의 죽습니다. 몇 마리를 휩쓸었는지 전투 로그에 표시됩니다.

## 사운드

**Web Audio API로 코드에서 직접 합성**합니다. 음원 파일이 없어 단일 HTML 구조가 유지되고 저작권 문제도 없습니다.
톤은 신스 계열 레트로 사운드입니다.

발사(산탄일 때 더 두껍게) · 명중 · 약점 명중 · **몬스터 쓰러짐(모든 사망, 위치 기반)** · **처치 확인음(내 처치만, 거리 무관)** · 폭발 · 피격 · 연속 처치(단계가 오를수록 음이 높아짐) ·
아이템 획득 · 무기 강화 · 웨이브 시작 · 대장 등장 경보 · 광폭화 · 카운트다운 · 부활 · 매치 종료 · UI 클릭.

- 우상단 버튼 또는 **M 키**로 음소거
- 위치 기반 효과음은 **34m 거리 감쇠**. 들리지 않을 볼륨이면 오실레이터를 만들지 않고 건너뜁니다
  (`exponentialRampToValueAtTime` 은 0을 받지 못해 예외가 납니다 — 실제로 겪은 버그)
- 효과음은 코드 합성, **배경음악만 음원 파일**을 씁니다(아래 참고)

효과음마다 `SFX` 객체 안에 함수가 하나씩이라 개별 수정이 쉽습니다.

`public/bgm/` 폴더의 파일을 씁니다(`BGM`).

화면 중심을 오른쪽으로 옮겨(`setViewOffset`) 왼쪽 메뉴와 겹치지 않게 합니다. 오른쪽 아래에 개발사 표기 `KIPIbara Games`.

`SHOTS` 배열에 **다섯 장면 × 5.5초(총 27.5초)** 가 정의돼 있고 끝나면 처음으로 돌아갑니다.

| # | 장면 | 구간 연출 |
|---|---|---|
| ① | 요원 등장 | 격납고 문에서 네 명 실루엣 → **1초짜리 개별 등장 4개(캐릭터마다 다른 동작, 아래 표)** → 네 명이 한 화면에, 줌아웃 |
| ② | 돌격 | 출발 자세 → 달리기 시작(줌인) → 전면 클로즈업(핸드헬드) → 로우 앵글 발걸음 → 후방 트래킹 와이드 |
| ③ | 발명이 | 문이 열리며 우르르 → 저각도 전진 트래킹 → 슬로우모션 + 흔들림 → 0.34초 컷으로 개별 샷 → 와이드→클로즈업 |
| ④ | 대립 | 좌 요원 · 우 발명이 원거리 대치 → 동시 돌진 → 0.38초 컷 근접 전투(섬광·타격) → 좌우 팬 → **전투를 내려다보다 카메라가 하늘로 고개를 든다**(어두워지지 않음) |
| ⑤ | 조형물 | 하늘의 탐조등을 따라 **틸트 다운하며 금빛 조형물이 드러남** → 오른쪽 앞에서 정면으로 크게 도는 스윕 → 양옆에서 요원들이 달려 들어와 조형물 앞에 섬 → 뒤돌아 자세 → 천천히 물러나며 전체 |

①의 개별 등장 동작(`INTRO_ACTS`):

| 요원 | 등장 |
|---|---|
| 정보요원 | 위에서 앞구르기로 뛰어내려 착지(먼지) → 고글 옆으로 경례 |
| 심사관 | 코트를 휘날리며 회전해 들어옴 → 안경을 치켜올리고 플라스크를 번쩍 |
| 분석관 | 달려오다 미끄러지며 제동 → 무기를 두 바퀴 돌려 정면 조준 · 발사 |
| 수호관 | 등을 보인 채 어깨 너머로 힐끗 → 휙 돌아서며 두 발을 딛고 블래스터를 치켜듦 |

- 출연진은 매 프레임 **발이 무대(또는 바닥) 아래로 내려가지 않게** 보정합니다(`keepOnFloor()`).
- ③에서 발명이가 머리를 박고 기어 오던 문제: ④에서 튕겨 날아간 발명이의 앞뒤 회전이 다음 반복의 ③까지 남아 있었습니다. ③에서 회전을 매 프레임 새로 정합니다.

- 각 장면 함수는 (경과초, 진행도)만 받아 **매 프레임 위치를 다시 계산**합니다. 상태를 남기지 않으므로 어디서 들어와도 그림이 같습니다.
- 카메라는 목표값을 **감쇠 보간으로 따라갑니다**(`camTo(..., cut, rate)`). 콘티가 빠른 컷을 요구하는 구간만 `cut=true` 로 즉시 전환합니다.
- 모션 규칙: 멈출 때 목표를 살짝 지나쳤다 돌아오고(`ezBack`), 그 순간 몸이 눌렸다 펴지며(`squash`), 팔은 다리보다 한 박자 늦고(`runPose`), 서 있어도 호흡·무게중심이 계속 흔들립니다(`readyPose`).

**KIPI 조형물**(`menuMon`)은 20세기 폭스 오프닝을 모티브로 한 **금빛 계단식 아르데코 기념탑**입니다. 글자·명판·엠블럼이 건물의 한 몸으로 붙어 있습니다.

| 층 (아래→위) | 구현 |
|---|---|
| 3단 계단 · 글자 받침 · 좌우 날개 기둥 | 둥근 모서리 상자, 세로 홈(핀) |
| **KIPI** | 글자 윤곽을 `Shape` 로 그려 `ExtrudeGeometry` 로 압출한 입체 글자(P 는 속이 뚫림). 정면 밝은 금 · 두께 짙은 금 |
| 본체 | 세로 홈이 글자 뒤로 솟는 벽 |
| **한국특허정보원** | 띠 정면에 음각 글자 질감(폰트 로딩 후 다시 그림) |
| 엠블럼 | '한국특허정보원' 띠 위에 크게 올라앉음. 회사 로고 외곽선 79점(`LOGO`)을 압출 — 정면 빨간 에나멜 · 두께 금테 |

- 재질은 조명 계산이 없는 `MeshBasicMaterial` 에 **면마다 다른 금색**(윗면 밝게 · 정면 · 옆면 어둡게)을 칠해, 스스로 빛나는 느낌을 가볍게 냅니다. ⑤ 시작 1초 동안 금빛이 차오릅니다.
- 뒤에서 탐조등 4줄기가 하늘을 훑고, 조형물 장면에서는 무대 가로등을 꺼서 앞을 가리지 않게 합니다.

### 디자인 규칙

모든 화면(메인 · 출전 준비 · 로비 · 가이드 · 랭킹 · 결과 · 일시정지 · HUD)이 `<style>` 맨 아래 `:root` 토큰 하나를 같이 씁니다. 새 UI를 넣을 때도 이 안에서만 고르세요.

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--ink` | `#0b1020` | 화면 바탕 |
| `--text` | `#f3f1ec` | 본문 |
| `--muted` | `#8d96a6` | 보조 글씨 (HUD 안에서는 밝은 `#c3c9d3`) |
| `--accent` | `#f0a93a` | 강조 — 주 버튼 · 선택 · 신기록 · 내 이름 |
| `--hp` / `--danger` / `--ally` | 초록 / 빨강 / 파랑 | 체력 · 위험(대장 체력, 처치) · 동료 |
| `--r` | `6px` | 모든 모서리 |

- 글꼴은 Pretendard 하나, 이모지 없음(아이콘은 선 SVG).
- 발광(glow) · 장식용 그라데이션 · 올라가는 hover 효과는 쓰지 않습니다. HUD 글씨는 `--lift` 그림자와 화면 아래쪽 옅은 어둠으로만 읽히게 합니다.
- 전투 현황 문구는 오른쪽 위 소식창입니다.
- **연속 처치**: 점수판 왼쪽 판에 **큰 숫자(몇 연속) · "연속 처치" · 점수 배율 배지 · 남은 시간 막대**. 처치할 때마다 숫자가 튀어 오르고, 6연속부터 주황 · 최대 배율이면 빨강, 끊기기 1.3초 전부터 막대가 깜빡입니다.
- **체력 위 이름**: "닉네임 · 요원 이름"(16px, 체력 숫자보다 작게).
- **점수 · 시간 판**: 같은 폭의 두 판에 위는 라벨(SCORE / TIME), 아래는 숫자.
- **체력 옆 요원 얼굴**: 고른 요원의 가슴까지 모습이 몸을 비스듬히 틀고 화면 오른쪽 아래를 보는 구도로 뜹니다. 판마다 3D 로 그리지 않고 요원별로 처음 한 번만 그려 이미지로 재사용합니다(`hudFace()`). 맞으면 빨갛게 흔들리고, 체력 30% 이하면 아래 막대가 깜빡입니다.

### 맵 사물 · 바닥 질감

외부 3D 파일 없이 전부 코드로 만듭니다. `index.html` 의 「소품 질감」 블록(`crateMat` 선언 바로 아래)에 모여 있습니다.

- `roundBoxGeo(w,h,d,r,tile)` — 모서리를 둥글게 깎은 상자. `slab()` 이 재질을 보고 자동으로 씁니다(`PX_SLAB` 표). `tile` 은 질감 반복 크기(m), `[가로, 세로]` 도 가능.
- `pxTex(w,h,seed,draw)` — 캔버스에 그린 질감. seed 가 같으면 매번 같은 무늬.
- 질감 종류: 나무 상자 · 골함석(벽/컨테이너) · 철판(옥상/계단/폐차) · 경고 방벽 · 드럼통 · 금속 파이프 · 콘크리트 · 타이어.
- 바닥: 흙·자갈 질감(8m 반복) + 스폰 야드/처리장/폐건물 안 콘크리트 판(`floorPad`) + 기름 얼룩 · 벽 밑 모래 · 바퀴 자국(`decal`).
- 충돌 판정(`collAt`)은 바꾸지 않았으므로 이동 · 엄폐 동작은 이전과 같습니다.
- 질감 도구(`pxTex`, `roundBoxGeo`)는 `const solid=[]` 바로 아래에 있어 배경 건물 · 메뉴 무대 · 캐릭터도 같이 씁니다.
- 배경 건물: `facadeTex` 가 창틀 · 유리 반사 · 블라인드 · 물때 · 줄눈을 그립니다(`LM_DETAIL` = 창 한 칸 픽셀). 덩어리 박스는 `stoneMat` 결.
- 캐릭터 · 발명이 · 1인칭 무기: 만든 직후 `softenParts()` 가 상자 모서리를 깎고, 곡면을 촘촘히 하고, 칠한 장난감 같은 잔결(`CHAR_GRAIN`)을 입힙니다. 피부 · 발광 · 유리 재질은 제외.
- 예전 '차원 포탈'(노란 테두리 검은 원) 장식은 삭제했습니다.

### 하늘 · 구름

멀리 하늘에 옅은 구름 스프라이트 11장(텍스처 3장)이 아주 천천히 흐릅니다. 테마마다 색·투명도가 바뀝니다(아침 흰색 · 노을 살구색 · 밤 거의 안 보이게).

### 선사유적지 움집

짚으로 엮은 움집 2채(`buildHuts()`) — ① 둥근 짚벽 위 원추 지붕 + 출입구 · 차양, ② 땅까지 내려오는 원추형 + 경사면 출입구. 새끼줄 띠 · 꼭대기 묶음 · 입구 앞 디딤돌, 주변은 풀밭 얼룩.
구석 후보 자리 중 구조물·시작 지점과 겹치지 않고 서로 22m 이상 떨어진 두 곳에 세웁니다. 들어갈 수 없고 몸통만 충돌합니다.

### 녹지

고철장 틈새에 자란 풀 · 꽃 · 나무. 과하지 않게, 구조물 발치와 방벽 가장자리 위주입니다(`buildGreenery()`).

- 풀 약 500포기(잎 5장짜리) · 꽃 약 90송이 · 벽 발치 덤불 무리 · 이끼 낀 땅 얼룩
- 나무 약 40그루: 방벽 바깥은 **크기가 다른 숲 무리 9곳**(큰 나무 1~2 + 중간·작은 나무) + 외톨이 나무, 방벽 안은 모서리 5곳(몸통만 충돌). 나무마다 키·폭·잎 덩어리 수(3~6)가 달라 풍성함이 제각각이고, 위쪽 잎은 조금 더 밝습니다.
- 전부 `InstancedMesh` 라 풀 1회, 꽃 2회, 나무 2회, 덤불 1회만 그립니다. 풀·꽃은 그림자를 만들지 않습니다.

## 성능 — 그래픽 카드가 없는 PC 에서도

가장 우선하는 원칙입니다. 새 장식을 넣을 때도 아래 구조를 지켜 주세요.

| 장치 | 내용 |
|---|---|
| 소프트웨어 렌더링 감지 (`PERF`) | 그래픽 카드가 없거나 성능 제한 경고가 뜨면 **안티앨리어싱 끔 · 해상도 배율 1 · 그림자 끔 · 점광원 축소**로 시작 |

| 정적 맵 합치기 (`mergeStaticMap`) | 벽·상자·드럼·파이프·사다리·장식 550여 조각을 재질별 24덩어리로. 조준 판정은 원래 조각을 화면 밖에서 그대로 사용 |

| 삼각형 줄이기 | 둥근 모서리 1단, 작은 조각은 각진 그대로, 곡면 분할 수를 크기에 비례 |

### 마우스 잠금 (Pointer Lock)

커서 위치로 시점을 돌리면 크게 휘두를 때 커서가 창 밖으로 나가 조작이 끊깁니다. 그래서 **전투 중에는 포인터를 화면에 잠급니다.**

- 커서가 숨고 창 밖으로 나가지 않으며, 마우스 **이동량**만큼 시점이 돕니다(`LOOK_SENS` = 1px당 0.0022 라디안).
- **재개는 기다리지 않습니다.** ESC를 다시 누르면 일시정지 화면이 즉시 닫히고 게임이 돌아갑니다. 포인터 잠금은 그 뒤에 조용히 다시 요청합니다.
  브라우저는 ESC 직후 약 1초간 재잠금을 거부하는데, 그 사이에도 게임은 커서 방식으로 정상 동작합니다.
- 잠금이 풀린 상태에서 **다음 입력(키 입력·마우스 이동)이 들어오는 순간 자동으로 다시 겁니다**(`autoRelock()`). 사용자에게 클릭을 요구하는 안내는 띄우지 않습니다.
- **클릭은 절대 삼키지 않습니다.** 잠금이 안 걸린 상태에서 좌클릭해도 발사가 나가고, 잠금은 같이 요청됩니다.
- ESC 토글에서 무시하는 경우는 하나뿐입니다. 브라우저가 잠금을 풀면서 이미 멈춘 **그 한 번의 누름**이 키 이벤트로 중복해 들어올 때(250ms).
- 창을 닫거나 탭을 떠나기 직전(`pagehide`/`beforeunload`)에 잠금을 **반드시 해제**합니다. 잠긴 채 문서가 사라지면 OS 커서가 숨은 채로 남는 브라우저가 있습니다.
  전투 중이라면 확인 대화상자도 띄워 Ctrl+W 같은 실수로 판이 날아가는 것을 막습니다.
- 탭 전환·알트탭(`visibilitychange`/`blur`)이면 잠금을 풀고 일시정지로 넘깁니다.
- 전투가 끝나거나 메뉴로 나가면 커서를 돌려줍니다. 잠금을 지원하지 않는 환경에서는 예전 커서 위치 방식으로 동작합니다.

## 2인 협동 플레이

### 구조 — 호스트 권위

방장 브라우저가 **몬스터 AI · 스폰 · 웨이브 · 타이머 · 테마**를 계산하고 초당 15회(`SEND_HZ`) 상태를 보냅니다.
게스트는 받은 좌표로 그리며 보간하고, **자기 조준과 명중 판정만** 합니다.

**서버는 방을 관리하고 메시지를 전달만 합니다.** 몬스터 계산이 각 팀 방장 PC로 분산되므로 방이 늘어도 서버 부하는 거의 늘지 않습니다.

### 처치 판정 — 중복 집계 방지

1. 각 클라이언트가 자기 화면에서 **명중 판정** (거리·약점 계산은 싱글과 동일)
2. 게스트는 `{적 id, 피해량}` 을 호스트에 보고
3. **호스트만** 체력을 차감하고, 0으로 만든 쪽을 처치자로 확정
4. 이미 죽은 적에 대한 **뒤늦은 피해 보고는 폐기**
5. 호스트가 처치 확정을 양쪽에 통보

체감을 위해 **명중 마커와 피해 숫자는 로컬에서 즉시**, **처치 연출·점수·연속 처치는 호스트 확정 후** 표시합니다.
맞은 감각에 지연이 없어 0.1초 정도의 처치 지연은 체감되지 않습니다.

### 점수 — 팀 합산

누가 막타를 넣든 팀 점수가 함께 오릅니다. 막타 분쟁이 구조적으로 발생하지 않습니다.
랭킹에는 팀 한 줄로 두 사람 이름이 같이 올라갑니다(`방장 & 동료`).

**기록은 방장만 등록합니다.** 방장이 서버에서 받은 순위를 `rank` 메시지로 동료에게 보내, 두 화면에 같은 순위가 뜹니다.

### 로비

방 **10개 고정(1~10번)**. 방 코드를 입력하지 않고 목록에서 고릅니다.

| 상태 | 동작 |
|---|---|
| 비어 있음 | 누르면 방장이 되어 방을 엽니다 |
| 대기 중 (초록) | 누르면 참가합니다 |
| 정원 참 / 플레이 중 | 흐리게 표시, 눌리지 않음 |

출전 준비(이름·캐릭터)를 **로비보다 먼저** 거칩니다. 방에 들어간 뒤 이름을 정하면 상대가 기다려야 하기 때문입니다.

### 동료 표시

- 초록색 요원 아바타, 위치·회전은 **보간** 처리
- 좌하단에 동료 체력바, 쓰러지면 표시가 바뀜
- 몬스터가 **동료도 타겟으로** 삼고, 동료가 맞으면 그쪽 화면에서 피해가 들어감

### 이탈 처리

| 상황 | 결과 |
|---|---|
| 게스트 이탈 | 호스트가 단독으로 이어서 진행 |
| 호스트 이탈 | 남은 게스트가 방장이 되어 단독 진행 |
| 서버 끊김 | 진행 중이던 판은 단독 모드로 전환 (판이 죽지 않음) |

재접속 복구는 범위에 없습니다.

### 통신 규약

서버는 `{t:'r', d:{...}}` 를 상대에게 그대로 전달합니다. `d.k` 가 메시지 종류입니다.

**호스트 → 게스트**

| k | 내용 |
|---|---|
| `w` | 월드 상태 — 몬스터 배열, 웨이브, 할당량, 남은 시간, 점수, 무기 레벨 |
| `kill` | 처치 확정 — 적 id, 처치자, 대장 여부, 갱신된 점수, 로그 |
| `wave` | 웨이브 전환 — 번호, 이름, 대장 여부 |
| `theme` | 맵 테마 번호 |
| `hurt` | 동료가 몬스터에게 맞음 |
| `ef` | 적이 쏜 마법공 — 출발·도착 좌표. 참여자 화면에 **연출 전용(ghost) 탄**으로 띄운다. 이게 없으면 참여자는 날아오는 탄이 전혀 안 보인 채 체력만 깎인다 |

| `end` | 매치 종료 — `lo` 가 1이면 목숨 소진으로 끝난 판 |
| `rank` | 방장이 등록한 팀 순위 — 순위, 전체 팀 수 |

몬스터 한 기는 `[id, x, y, z, ry, hp, maxHp, variant, boss, alive, skin, sizeMul]` 배열입니다.

| k | 내용 |

**양방향**

| k | 내용 |
|---|---|

## 랭킹 서버

DB 없이 **CSV 파일 한 장**에만 append 합니다.

| 엔드포인트 | 내용 |
|---|---|
| `POST /api/scores` | 점수 등록 → `{ok, rank, total}` |
| `GET /api/ranks?mode=solo\|coop&limit=10` | 상위 기록 조회 |
| `GET /api/ranks.csv` | 전체 기록 CSV 다운로드 (엑셀용 BOM 포함) |
| `WS /ws` | 협동 릴레이 |

**서버를 재시작하면 기록이 초기화됩니다.** 행사 한 회차 = 서버 한 번 실행이라는 의도된 동작입니다.

CSV 컬럼: `timestamp, mode, name, partner, character, score, kills, wave`
이름에 쉼표가 들어가도 깨지지 않도록 이스케이프 처리되어 있습니다.

클라이언트는 `API_BASE` 상수 하나로 제어합니다. 같은 도메인에서 서빙하면 빈 문자열이면 충분하고, API를 다른 곳에 두려면 여기만 바꾸면 됩니다.

## 코드 구조 메모

**한 프레임 갱신은 `step(dt)` 로 분리**되어 있고 `loop()` 은 `requestAnimationFrame` 으로 이를 호출하기만 합니다.
프레임 소스와 갱신 로직이 나뉘어 있어 협동 상태를 주입하기 쉽습니다.

### 권한 분기

협동 관련 분기는 세 개의 헬퍼로만 판단합니다.

```js
isCoop()   // 협동 모드인가
isHost()   // 호스트인가 (싱글은 항상 true)
isGuest()  // 협동이면서 게스트인가
```

게스트에서 차단되는 것: `spawnInventor` · `spawnBoss` · `tickSpawner` · `checkWaveClear` · 타이머 감소 · 아이템 재생성.

**대장 체력바**도 갈라집니다. 참여자의 `entities` 에는 대장이 없고(대장은 `mateEnts` 에 산다) `updateBossBar()` 는 대장을 못 찾으면 바를 숨깁니다.
그래서 매 프레임 `updateBossBar()` 를 부르면 바가 **초당 60번 꺼지고** 월드 패킷이 올 때(초 15회)만 켜져 깜빡였습니다.
`step()` 에서 `isGuest()? ghostBossBar() : updateBossBar()` 로 갈라 줍니다.

아이템 위치도 양쪽이 각자 무작위로 놓으므로(`resetMatch()` → `placePickup()`) 판이 시작될 때 방장이 `itemon` 으로 전부 한 번 맞춰 줍니다.

### 캐릭터 모델을 추가하려면

`group.userData` 계약만 지키면 모션 코드는 손대지 않아도 됩니다.

```
플레이어 : limbs {armL,armR,legL,legR} · wand(무기 그룹) · muzzle · mflash · flashMat · labelY
발명이   : limbs {armL,armR,legL,legR} · flashMat(팀 색, emissive 필요) · labelY
```

무기는 **로컬 +z 가 발사 방향, 원점이 쥐는 지점**이라는 축 규약만 지키면 겨눔/내림 자세는 엔진이 X축 ±90° 회전으로 알아서 만듭니다.

머리 중심은 플레이어 `y=1.75`, 발명이 `y=1.4` 에 고정되어 있습니다. **약점(헤드샷) 판정이 이 높이를 상수로 쓰기 때문에**,
외형을 바꿔도 판정은 건드리지 않아도 됩니다. 발명이 외형은 `NPC_BUILD` / `NPC_SKIN_NAMES` 배열에 나란히 추가하면 웨이브 순환에 자동으로 들어갑니다.

### 주요 튜닝 상수

| 상수 | 값 | 의미 |
|---|---|---|
| `MATCH_TIME` | 180 | 한 판 길이(초) |
| `WAVES[].quota` | 12/17/21/25/∞ | 웨이브별 처치 할당량 |
| `WAVES[].max` | 8/10/10/12/14 | 동시 최대 마리 |
| `NPC_BASE_HP` / `NPC_WAVE_HP` | 34 / 16 | 발명이 기본 체력 / 웨이브당 증가 |
| `NPC_CHASE` / `NPC_HUNT` | 2.15 / 1.9 | 추격 / 사냥 이동 속도 |
| `LEVEL_KILLS` | 14 | 무기 레벨업 주기 |
| `BOSS_RAGE` | 0.45 | 광폭화 체력 비율 |
| `BOMB_RADIUS` / `BOMB_DMG` | 9.5 / 300 | 폭탄 반경 / 중심 피해 |
| `SPAWN_COUNT` / `SPAWN_APART` | 18 / 7 | 매치당 스폰 지점 수 / 최소 간격 |
| `ITEM_RESPAWN` | 30 | 아이템 재생성 대기(초) |
| `NET.SEND_HZ` | 15 | 협동 상태 전송 빈도 |

## 남은 작업 / 알려진 제약

- **실제 2인 동시 플레이 검증 미완.** 프로토콜·동기화 로직·권한 분리는 테스트로 확인했으나,
  브라우저 두 개를 띄운 실플레이에서 보간이 자연스러운지와 지연 체감은 직접 확인이 필요합니다.
- 배경음악은 전투 구간만 있음 (메뉴·로비·결과 화면은 없음). 메인 시네마틱에도 음악·효과음이 없습니다.
- 조작이 마우스·키보드 기반이라 **모바일·태블릿은 사실상 플레이 불가**. WebGL 지원 브라우저 필요.
- 협동은 한 방 2인 고정. 3인 이상, 재접속 복구, 관전 모드는 범위 밖.
